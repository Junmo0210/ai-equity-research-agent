# A-1 Financial Data Engine — 설계 문서

- 프로젝트: AI Equity Research Agent
- 모듈: A-1 Financial Data Engine (기업분석 자동화의 첫 모듈)
- 상태: **설계 승인 완료 (2026-11-11), 개발 전**
- 문서 성격: 사용자와 합의한 요구사항·설계 결정의 기준 문서. 중요한 설계 변경은 이 문서를 먼저 고치고 사용자 승인을 받은 뒤 개발한다.

---

## 1. 목표와 범위

### 1.1 목표
기업명을 입력받아 OpenDART에서 **사업보고서 기준 연결재무제표**를 수집하고, 원본 출처를 보존한 채 Excel로 정리하며, 기본 회계 검증과 원본 대사를 수행한다.

### 1.2 초기 대상
- 회사: **삼성전자**
- 사업연도: **2021 ~ 2025**
- 진행 순서: FY2025 **한 개 연도로 먼저 테스트** → 2021~2025로 확대

### 1.3 범위 밖 (이번 모듈에서 개발하지 않음)
실적 추정, DCF, 투자 의견, AI 보고서, 대시보드, 분기·반기 보고서, 전체 표준계정 매핑(→ A-2).

### 1.4 장기 로드맵 (참고)
A. 기업분석 자동화 → B. 다중 에이전트 기반 AI 애널리스트 → C. 종합 투자 리서치 플랫폼.
A-1은 지금 필요한 것만 만들되, 각 기능을 "입력 스키마 → 출력 스키마" 함수로 만들어 B단계에서 Agent 도구로 감쌀 수 있게 한다.

## 3. OpenDART API 사용 계획

> 아래 엔드포인트·필드·상태코드는 OpenDART 개발가이드 기준으로 작성했으며, **구현 시 공식 문서와 실제 응답으로 재확인**한다 (12장 미확인 사항).

| 용도 | 엔드포인트 | 주요 파라미터 |
|---|---|---|
| 회사 고유번호 목록 | `corpCode.xml` (ZIP 안의 XML) | `crtfc_key` |
| 공시 목록(정정 대사) | `list.json` | `corp_code`, `bgn_de`, `end_de`, `pblntf_ty=A`, `pblntf_detail_ty=A001`, `last_reprt_at`(Y/N), `page_no`, `page_count` |
| 단일회사 전체 재무제표 | `fnlttSinglAcntAll.json` | `corp_code`, `bsns_year`, `reprt_code=11011`, `fs_div=CFS` |

### 3.1 전체 재무제표 응답 필드 (모두 원본 보존)
`rcept_no`, `reprt_code`, `bsns_year`, `corp_code`, `sj_div`(BS/IS/CIS/CF/SCE), `sj_nm`, `account_id`, `account_nm`, `account_detail`, `thstrm_nm`, `thstrm_amount`, `thstrm_add_amount`, `frmtrm_nm`, `frmtrm_amount`, `frmtrm_q_nm`, `frmtrm_q_amount`, `frmtrm_add_amount`, `bfefrmtrm_nm`, `bfefrmtrm_amount`, `ord`, `currency`

### 3.2 상태코드 처리
| 코드 | 의미 | 처리 |
|---|---|---|
| 000 | 정상 | 저장 |
| 013 | 조회된 데이터 없음 | CFS 없음 → 검토 대상 기록 (OFS 호출 안 함) |
| 010, 011, 012, 901 | 키 미등록·사용불가·IP 불가·만료 | 즉시 중단, 키 값 없이 원인만 안내 |
| 020 | 요청 제한 초과 | 중단 후 안내 (재시도 루프 금지) |
| 800 | 시스템 점검 | 중단 후 안내 |
| 그 외 (100, 101, 900 등) | 파라미터·기타 오류 | 중단, 응답 메시지 기록 |

네트워크 오류·5xx만 지수 백오프로 최대 3회 재시도한다.

## 4. 데이터 모델

### 4.1 RawLine (원본 1행 × 1기간)
API 응답 1행을 기간별(당기/전기/전전기)로 펼친 단위. 모든 금액 셀의 출처 추적 기준.

| 필드 | 설명 |
|---|---|
| corp_code, bsns_year, reprt_code | 보고서 식별 |
| rcept_no | 공시 접수번호 |
| fs_div | CFS |
| sj_div, sj_nm | 재무제표 구분·명칭 |
| account_id | XBRL 계정ID (비표준: `-표준계정코드 미사용-`) |
| account_nm, account_detail | 원본 계정명·상세 |
| ord | 원본 표시순서 |
| period | `thstrm` / `frmtrm` / `bfefrmtrm` |
| period_nm | 원본 기간명 (예: 제57기) |
| fiscal_year | 해당 금액의 회계연도 (bsns_year, bsns_year−1, bsns_year−2) |
| amount | 정수 또는 None (공란·`-`) |
| amount_raw | 원본 문자열 |
| currency | 원본 통화 |
| source_file, source_sha256 | 저장된 원본 JSON 파일명·해시 |

### 4.2 계정 식별 키 (연도·보고서 간 정렬)
- 표준계정: `(sj_div, account_id)`
- 비표준계정: `(sj_div, 정규화된 account_nm)` — 공백 제거 수준만 정규화
- 계정명이 바뀌면 자동 병합하지 않고 별도 행 + 플래그
- 한 재무제표 안에서 같은 키가 중복되면 검토 대상

### 4.3 매핑 상태
`MAPPED`(account_map.csv의 계정ID와 정확 일치) · `NONSTANDARD_REVIEW` · `UNMAPPED`(표준계정이지만 핵심 항목 아님 — 정상) · `CRITICAL_MISSING_REVIEW`(검증에 필요한 핵심 항목을 찾지 못함)

## 5. 기준값 선택 정책 (D-03)

각 (회계연도, 계정)의 기준값은 **그 회계연도를 담고 있는 가장 최근 사업보고서**에서 가져온다.

| 회계연도 | 1순위 | 대체 순서 (1순위에 값이 없을 때) |
|---|---|---|
| FY2025 | FY2025 보고서 당기 | — |
| FY2024 | FY2025 보고서 전기 | FY2024 보고서 당기 |
| FY2023 | FY2025 보고서 전전기 | FY2024 보고서 전기 → FY2023 보고서 당기 |
| FY2022 | FY2024 보고서 전전기 | FY2023 보고서 전기 → FY2022 보고서 당기 |
| FY2021 | FY2023 보고서 전전기 | FY2022 보고서 전기 → FY2021 보고서 당기 |

규칙
1. 금액 셀마다 **출처 접수번호와 기간**(당기/전기/전전기)을 기록한다.
2. 1순위에 값이 없어 대체 출처를 쓰면 "대체 출처" 플래그를 달고 확인 대상 목록에 올린다.
3. 같은 (회계연도, 계정)에 대해 출처 간 값이 다르면 **재작성 로그**에 모든 후보값·차이·접수번호를 기록한다.
4. 최신 보고서에 없는 계정(과거 보고서에만 존재)은 과거 출처로 표시하되 "최신 보고서 미존재" 플래그를 단다.
5. 새 사업보고서가 공시되어 재실행하면 과거 연도 값이 갱신될 수 있다. 결과 파일명에 생성일을 붙여 이전 결과를 덮어쓰지 않는다.

## 6. 처리 흐름

```
[1] 회사 식별   corpCode.xml(캐시) → 정확 일치 상장사 1건 → 고유번호 확정 (아니면 후보 제시·중단)
[2] 공시 목록   list.json → 연도별 사업보고서 접수번호, 기재정정 이력
[3] 수집        연도별 fnlttSinglAcntAll(fs_div=CFS)
                 ├ 000 → 원본 JSON 저장(키 제외) + SHA-256
                 └ 013 → "CFS 없음" 검토 대상 기록, OFS 호출 안 함
[4] 펼치기      응답 행 → RawLine(기간별)
[5] 분류        표준 여부, 매핑 상태 (account_map.csv)
[6] 기준값 선택  5장 정책, 셀 단위 출처
[7] 재작성 대사  출처 간 값 비교 → 재작성 로그
[8] 검증        9장
[9] Excel       7장
```

## 8. 보안 (D-12)

- 키는 `os.environ["DART_API_KEY"]`로만 읽는다. 기본값·하드코딩 금지. `.env` 사용 시 `.gitignore`에 포함.
- OpenDART는 키를 URL 쿼리(`crtfc_key`)로 받으므로 `requests` 예외 메시지에 전체 URL이 포함될 수 있다. 대응:
  - 로깅 필터로 `crtfc_key=...` 및 키 문자열 자체를 마스킹
  - 예외는 키를 제거한 자체 메시지로 재발생
  - 원본 JSON 저장 시 요청 파라미터에서 키 제거
  - 캐시 파일명·키에 인증키 미사용
- 최종 점검: `output/`, `logs/`, `data/` 전체에서 키 문자열 검색 **0건**을 테스트로 확인.

## 9. 검증

### 9.1 회계 검증 (연도별, 기준값 기준 + 보고서 원본 당기 기준)
| ID | 규칙 | 계정 부재 시 |
|---|---|---|
| V1 | 자산총계 = 부채총계 + 자본총계 | REVIEW |
| V2 | 자본총계 = 지배기업 소유주지분 + 비지배지분 | REVIEW |
| V3 | 매출총이익 = 매출액 − 매출원가 | N/A |
| V4 | 기초현금 + 현금증감(환율효과 전) + 환율변동효과 = 기말현금. 환율효과 전 증감 계정이 없으면 기초현금 + 현금증감(환율효과 포함) = 기말현금 (D-16) | REVIEW |
| V5 | 현금흐름표 기말현금 = 재무상태표 현금및현금성자산 | REVIEW |
| V6 | 손익계산서 당기순이익 = 포괄손익계산서 당기순이익 (둘 다 있을 때) | N/A |

- 허용오차 기본 0 (`settings.yaml`에서 사용자가 조정). 차이는 금액 그대로 보고.
- 상태: PASS / FAIL / REVIEW(판단 불가) / N/A. **계정 부재를 PASS로 처리하지 않는다.**

### 9.2 원본 대사
- R1: 재무제표별 원본 행 수·금액 합계 = 시트 집계
- R2: 저장된 Excel을 다시 읽어 모든 금액 셀 = 출처 RawLine 값 (자동)
- R3: 모든 행에 접수번호 존재, 통화 단일성
- R4: 재무제표 API 접수번호 = 공시검색 기준 최종 정정본 접수번호

### 9.3 사용자 검증
Validation 시트 스팟체크 목록으로 주요 계정 10여 개를 DART 공시 원문과 대조.
